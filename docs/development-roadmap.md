# 개발 로드맵과 현재 범위

사용자가 Phase 1 검토 후 Phase 2–6 진행을 승인했습니다. 단일 전역 LLM, 결정론적 SIZE/FILLS/RISK, PAPER ONLY를 유지합니다.

## 구현·검증 상태

| 단계 | 구현한 내용 | 현재 제한 |
| --- | --- | --- |
| Phase 1 | 원문 전체 확인, 7개 설계 문서, API 조사, 원문 수치 검산 | 원문 자체가 정하지 않은 부분은 구현 해석에 별도 기록 |
| Phase 2 | HTTP 6종 + CLI 8종·브리지·로컬 CPU Adapter, 전역 설정·schema probe·사용량 기록 | 로컬 모델 네 역할 실제 추론 통과. 유료 외부 모델과 CLI 계정 추론은 미검증 |
| Phase 3 | Dex·WM·venue·Solana 읽기 Adapter, Redis/REST·공식 WM seed, 선택 관측 feed | WM fear/greed·prediction 실제 수집, 교차 신호 미생성. RPC 429·필수 보유자/whale/체결 자료 미확보 |
| Phase 4 | 자동 모델 점검·수집·15분 SCAN/BOOK·5분 RISK·서울 23시 보고, 감독·lease | 실제 작업 반복 실행 확인. 거래 판단 품질·장기 운용과 완전한 원본 시장자료 경로는 미검증 |
| Phase 5 | 가상 1000달러, Decimal, 비용·슬리피지·부분 체결·멱등성·원장·감사·Kill Switch, 독립 재생 | 실제 시장 자료의 연속 운용·수익성은 미검증 |
| Phase 6 | Streamlit 12개 화면, 자동 상태·준비도 API, 인증 운영 API, BOOK 자동 입력·확정 결과 정산 | 전역 설정 변경 후 관련 서비스 재시작. BOOK은 WM·호가·근거가 준비돼야 실행 |

코드와 mock/fixture 검증을 제공한 상태입니다. 외부 조건까지 모두 충족된 자동 모의매매의 운영 준비 완료로 표시하지 않습니다.
현재 테스트 결과와 실제 서비스 상태는 [검증 보고서](validation-report.md)를 기준으로 합니다.

## 남은 실행 조건

1. 현재 로컬 CPU 모델의 실제 네 역할 probe는 통과했습니다. 다른 Provider를 선택하면 해당 모델을 다시 probe해야 합니다.
2. 로컬 WM Redis REST/seed는 구성됐고 두 경로의 실제 자료가 있습니다. 최근 교차 신호와 거래 질문에 직접 관련된 근거는 계속 확보해야 합니다. hosted fallback은 없습니다.
3. 보유자 이력, 서로 겹치지 않는 거래 구간, whale 매도와 timestamp가 있는 실행 깊이의 신뢰할 수 있는 연속 자료가 필요합니다.
4. 이 자료로 엔드투엔드 모의 운영을 수행하고, 차단·복구와 운영 시간 동안의 장부 일치를 다시 확인해야 합니다.

## Phase 7 — 후속 장기 검증

같은 자료·기간·정책·비용·초기 자금으로 전역 모델을 실행 사이에 교체해 순차 비교합니다.
실행별로 새 계정을 사용하고 자료 해시·정책 버전·모델·입출력·실패·사용량을 보존합니다.
재생 기능이 있다는 사실은 이미 모델 비교 실험이 수행됐다는 뜻이 아닙니다.

후속 실험 항목:

- 시간 순서 검증, 과거 자료의 미래 정보 혼입 점검, 모델 사전 지식에 대한 한계 공개.
- 순손익, 최대 낙폭, 전체 청산 거래 승률·Profit Factor, 판단 일치율과 공동 유효 표본 수.
- 오류율·응답 지연·API 추정 비용·비용 차감 순손익.
- 실제 확정 결과가 쌓인 예측의 Brier score·보정 곡선·out-of-sample 평가.
- 반복 실험과 신뢰 구간. 무거래·손실 분모 없음·평가 불가 자료는 N/A와 원인을 공개.

장기 검증, 수익성 입증, 통계적 우월성은 이번 구현의 완료 항목에 포함하지 않습니다.
