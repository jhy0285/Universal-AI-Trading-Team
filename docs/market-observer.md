# 무료 시장 관측

DexScreener가 제공하지 않는 원천 관측 시각, 보유자 이력, 큰 지갑 매도, 실행 가능한 깊이를 무료 공개 자료로 채웁니다.
구현은 [observer.py](../src/trading_team/observer.py)와 [data.py](../src/trading_team/data.py)의 `SolanaOnchain`에 있습니다.
모두 읽기 전용 조회입니다. 스왑 거래 생성·서명·지갑 연결 경로는 없습니다.

## 후보 탐색

원문은 후보를 DexScreener 런치 데이터에서만 찾습니다. 기본값 `DEX_DISCOVERY=launches`는 최신 token profile·boost 피드의 Solana 토큰 최대 30개를 읽고,
`/tokens/v1/solana/...`로 해당 pool을 조회합니다. `search`는 `DEX_QUERIES` 검색어, `both`는 둘 다 사용합니다.
보유자 조회 한도(token account 3만 개)를 넘는 대형 토큰은 보유자가 unknown으로 남으므로 신규 상장 토큰이 원문 전략에 맞습니다.

## 자료 출처

| 필드 | 출처 | 키·비용 |
| --- | --- | --- |
| `observed_at`, `price`, `buy_quote` | Jupiter `GET /swap/v1/quote`를 크기별로 호출한 견적 사다리. 시각은 견적 slot의 Solana `getBlockTime` | 키 없이 30회/분. 무료 키 60회/분 |
| `holder_count`, `holder_observed_at` | Solana RPC `getProgramAccounts`로 mint의 모든 token account의 소유자·수량만 조회 | 공개 RPC 무료 |
| `largest_token_account_share`, `onchain_*` | 같은 조회의 소유자별 합계 중 유동성 풀이 아닌 최대 보유자 / 총 공급량 | 공개 RPC 무료 |
| `contract_safe`, `contract_source` | `getAccountInfo` mint 권한과 Token-2022 확장 | 공개 RPC 무료 |
| `previous_*` | 이 장부가 5–30분 전에 저장한 같은 pool의 관측 | 자체 DB |
| `windows` | GeckoTerminal pool trades의 체결 시각·방향 | 키 없이 30회/분 |
| `large_holder_selling` | 같은 trades의 매도자 ∩ 최대 보유자 상위 20 | 키 없이 30회/분 |
| `sell_quote` (RISK) | 보유 수량에 대한 Jupiter 매도 견적 사다리 | Jupiter와 동일 |

유동성·거래량·시가총액·pair 생성 시각은 기존대로 DexScreener에서 같은 수집 중에 읽습니다.
해당 값에는 공급자 시각이 없으므로 `fetched_at`과 Jupiter `observed_at`이 모두 300초 이내일 때만 SCAN 대상이 됩니다.

## 구현 해석

| 항목 | 이 구현의 선택 |
| --- | --- |
| 실행 깊이 | 최대 크기의 1/16·1/4·1/2·1배 누적 견적 차이를 한계 가격 단계로 사용. 가격은 보수적 방향으로 단조화. 실제 호가창이 아니라 Jupiter 경로 견적 |
| 최대 크기 | 매수는 `2 × max(50, PAPER_INITIAL_CASH × 6%)` USD. 매도는 보유 수량 |
| 가격 단위 | USDC를 USD로 간주. 디페그는 반영하지 않음 |
| 관측 시각 | 사다리 견적 중 가장 오래된 slot의 블록 시각. 수집 시각으로 대체하지 않음 |
| 보유자 | 수량이 0보다 큰 token account의 소유자 수. 유동성 풀은 지갑이 아니므로 제외 |
| 최대 보유자 | 원문의 “가장 큰 지갑”에 맞춰 같은 소유자의 token account를 합산하고 유동성 풀을 제외. 필드 이름은 호환을 위해 유지 |
| 유동성 풀 판정 | 이 mint의 DexScreener pair 주소, 그리고 실제 pool vault로 확인한 공용 권한 주소(Raydium AMM v4·CPMM, Meteora DAMM v2·DBC). 확인하지 않은 유형은 지갑으로 계산해 더 엄격하게 판정 |
| 계약 점검 | mint·freeze 권한이 없고, Token-2022는 `metadataPointer`·`tokenMetadata` 외 확장이 없을 때만 안전. 포괄적 감사가 아님 |
| 보유자 이력 | 같은 pool의 자체 관측 중 현재보다 5–30분 앞선 가장 최근 값. 없으면 unknown이며 VET가 차단 |
| 두 구간 | Jupiter 관측 시각까지의 연속된 5분 구간 두 개. 300건 한 페이지가 첫 구간 시작에 닿지 않으면 불완전으로 보고 unknown |
| 큰 지갑 매도 | 위 10분 안에 최대 보유자 상위 20 지갑이 매도자(`tx_from_address`)로 나타나면 true. 잔고 감소만으로 판단하지 않음 |
| 처리 예산 | 수집마다 유동성 1만 달러 이상인 Solana 자산을 유동성 순으로 최대 `MARKET_OBSERVER_MAX_ASSETS`의 3배까지 무료 보유자 조회로 먼저 검사. 최대 보유자 5% 초과·계약 미검증·조회 불가인 pool은 Jupiter 견적 없이 VET와 같은 사유로 SCAN 단계에서 기록하고, 통과한 pool 최대 `MARKET_OBSERVER_MAX_ASSETS`개만 견적 |
| 큰 토큰 | token account 3만 개 또는 응답 10MB를 넘으면 보유자 조회를 중단하고 1시간 동안 재시도하지 않음. 보유자는 unknown |

거래 구간·큰 지갑 매도는 SCAN이 평가하는 수집에서만 조회하고 429를 15초 뒤 두 번까지 재시도합니다. 1분 수집은 GeckoTerminal을 호출하지 않습니다.
VET를 통과한 후보는 체결 직전에 Jupiter 깊이를 다시 조회합니다. 모델 추론 시간 때문에 견적이 60초 한도를 넘지 않게 하기 위함입니다.
한 출처가 실패해도 다른 출처의 관측은 저장합니다. 실패한 필드는 unknown으로 남고 해당 진입은 결정론적 게이트에서 차단됩니다.
GeckoTerminal 거래 목록의 색인 지연은 알 수 없으므로 마지막 구간의 최근 체결이 늦게 반영될 수 있습니다.

## 설정과 비용

```dotenv
MARKET_OBSERVER_ENABLED=true
MARKET_OBSERVER_MAX_ASSETS=3
# 선택: Jupiter 포털의 무료 키. 비워 두면 키 없이 동작합니다.
JUPITER_API_KEY=
```

기본 구성은 **비용 없이** 동작합니다. 모든 출처가 키 없는 공개 API이며 요금이 청구되는 호출은 없습니다.
자산 하나를 관측할 때 Jupiter 4회, Solana RPC 4회, DexScreener 1회, GeckoTerminal 1회를 호출합니다.
Jupiter와 GeckoTerminal 호출은 자체 간격(키 없이 2.2초)을 두고, Jupiter 429는 10초 뒤 두 번까지 재시도합니다.

| 상황 | 권장 조치 | 비용 |
| --- | --- | --- |
| Jupiter 429가 잦음 | Jupiter 포털 무료 키를 `JUPITER_API_KEY`에 설정 | 무료 |
| GeckoTerminal 429가 지속 | 데이터센터·공유 IP에서 흔함. 개인 PC에서 실행 | 무료 |
| 공개 Solana RPC 429·시간 초과 | 키 있는 RPC를 `SOLANA_RPC_URL`에 설정. **홀더 스캔(`getProgramAccounts`)을 허용하는 무료 등급이어야 합니다.** Helius 무료는 허용(2026-11-09 실측), Alchemy 무료는 막힘(429). `SOLANA_RPC_URL`은 query 키를 허용하지 않고 앱은 키 헤더를 보내지 않으므로, 키를 헤더로 붙여 주는 프록시가 없는 환경에서는 쓸 수 없음(아래) | 무료 등급 |
| 더 많은 자산·짧은 주기 | 유료 RPC·CoinGecko 유료 플랜 | 유료, 선택 사항 |

공개 API의 무료 이용 조건과 한도는 공급자가 바꿀 수 있습니다. 장기 무료를 보장하지 않습니다.

### 수집 시간 예산

수집 한 번이 걸리는 시간은 대략 `관측 풀 수 × 풀당 Jupiter 4회 × 호출 간격 + RPC·Dex 시간`입니다. 키 없이는 간격이 2.2초라 풀당 약 9초, 무료 키가 있으면 1.1초라 약 4.5초입니다.
수집 주기보다 길어지면 다음 수집이 건너뛰어집니다(`max_instances=1`). 2026-11-02 실측(클라우드 공유 IP, 키 없음, Sonnet 5.5):

| 설정 | 수집 | 건너뜀 | 수집 시간 | 관측된 풀 / 본 자산 |
| --- | --- | --- | --- | --- |
| 3풀 · 60초 주기 | 약 90회 | 1 | 한 번에 60초 안 | 8 / 49 (90분) |
| 6풀 · 60초 주기 | 약 95회 | **30** | 60초를 자주 넘김 | 15 / 73 (125분) |
| 8풀 · 120초 주기 | 54회 | **0** | 중앙값 64.5초, p90 93.6초, 최대 110.1초 | 11 / 50 (120분) |
| 10풀 · 60초 주기, 무료 Jupiter 키 (공용 Solana RPC) | 112회 | 5 | 중앙값 34.6초, p90 44.4초, 최대 85.1초 | 18 / 47 (120분) |
| **10풀 · 60초 주기, 무료 Jupiter 키 + Helius 무료 Solana RPC** | 120회 | **0** | 중앙값 30.7초, p90 36.3초, 최대 51.2초 | 16 / 43 (120분) |

**상한은 20풀입니다(2026-11-11부터, 이전 10).** 10풀을 넘기면 무료 Jupiter 키가 있어야 하고 수집 간격이 `풀 수 × 6초` 이상이어야 합니다. 그렇지 않으면 설정 단계에서 거부합니다(풀당 실측 약 3.6초, p90 4.7초에 여유를 둔 값). 15풀이면 90초 이상입니다.
**다만 상한을 올려도 관측 수는 거의 늘지 않았습니다(2026-11-11 실측).** 관측기는 매 수집에서 새로 상장된 풀(약 30개) 중 유동성 1만 달러 이상인 것만 보유자 집중도를 검사하고, 통과한 것만 관측합니다. 수집당 검사한 풀은 상한 10일 때 약 10.8개, 15일 때 약 10.2개였고, 관측한 풀(Jupiter 견적 4건 = 1풀)은 약 7.2개와 7.8개였습니다. 병목은 상한이 아니라 조건을 넘는 새 풀의 공급입니다. 실제로 넓히려면 후보 공급(`DEX_DISCOVERY` 등)을 바꿔야 하는데, 이는 전략의 후보 정의를 바꾸는 일이라 하지 않았습니다.
키 없이는 8풀·120초가 거의 한계입니다(최대 110초가 120초에 가깝습니다). **무료 Jupiter 키가 있으면 10풀·60초가 맞습니다(2026-11-09 실측: 중앙값 34.6초, 112회 중 5회만 60초 초과).**
이때 공용 Solana RPC는 수집 112회 중 97회에서 429를 내(에러 125건) 보유자·온체인 자료를 못 받는 풀이 생겼습니다(`ONCHAIN_UNAVAILABLE` 13건). **홀더 스캔을 허용하는 키 있는 RPC(Helius 무료)로 바꾸자 120회 모두 오류 0, `ONCHAIN_UNAVAILABLE` 0건이었고 모델 심사(VET)가 6회에서 19회로 늘었습니다.** 시간대가 달라 RPC만의 효과로 분리해 말할 수는 없습니다.
주기를 늘리면 건너뜀은 없어지지만 발견하는 신규 상장과 관측되는 풀이 줄 수 있습니다. 위 표의 세 실행은 시간대와 시장 상황이 달라 주기의 효과만 분리해 비교할 수 없습니다.
8풀 실행에서 수집 오류는 54회 중 공용 Solana RPC 429가 5건, 실행 견적 413이 1건이었습니다(`AUTONOMOUS_COLLECT_SECONDS=120`, `MARKET_OBSERVER_MAX_ASSETS=8`).

### 키 있는 Solana RPC 고르기 (2026-11-09 실측)

앱이 RPC에서 쓰는 호출은 `getAccountInfo`, `getBlockTime`, `getProgramAccounts`(홀더 스캔)입니다. 앞의 둘은 어느 무료 키에서나 되지만 **홀더 스캔이 공급자의 무료 등급에서 막힐 수 있습니다.**

| 공급자(무료) | 홀더 스캔 | 비고 |
| --- | --- | --- |
| 공식 공용 RPC | 되지만 공유 IP에서 429 | 이 클라우드에서는 수집의 약 87%(97/112회)에서 오류 |
| Alchemy 무료 | **429로 막힘**(`getProgramAccountsV2`는 "Free에서 사용 불가"라고 명시) | 헤더 인증은 됨. Pay As You Go(100만 CU당 $0.52)에서 풀리는지는 미시험 |
| Helius 무료 | **됨**(초당 5회) | 월 1M 크레딧. 문서는 이 호출을 10크레딧이라 하지만 실제 대시보드는 호출당 1로 센 것으로 보여(2시간 4,287회 = 4,287) 상시 가동 약 19일치입니다. 키는 문서상 URL 쿼리이고 헤더(`x-api-key`)로 통과함을 확인 |

앱은 RPC 요청에 `User-Agent`만 싣고 `SOLANA_RPC_URL`의 query 키를 거부합니다. 이 클라우드에서는 프록시가 키를 헤더로 붙여 주어 `SOLANA_RPC_URL=https://mainnet.helius-rpc.com`만으로 동작했습니다. 프록시가 없는 환경에서 키 있는 RPC를 쓰려면 앱에 키 헤더 설정을 추가해야 하며 **아직 구현하지 않았습니다**(Jupiter 키가 `x-api-key` 헤더로 가는 방식이 선례).

### 24시간 실측 (2026-11-10~11)

Helius 무료 RPC · 10풀 · 60초로 24시간: 수집 1,388회(중앙값 35.6초), 관측 풀 106개, 판단 3,054건 전부 차단(1위 `STALE_OR_UNKNOWN_MARKET_TIME` 68% = 관측 범위), VET 90건 전부 REJECT, 체결 0. 기록된 Helius 호출은 55,233건(호출당 1크레딧으로 보면 하루 약 5.5만, 한 달이면 문서상 무료 100만을 넘음)이고 DB는 하루 226MB(수집당 약 163KB)였습니다. 표와 다운타임은 [검증 보고서](validation-report.md). 차단된 후보의 1시간 뒤 평균 수익이 −2.5%(관측값 없음)~−4.2%로 왕복 수수료 문턱 4.9%에 못 미쳐, 관측 범위를 넓혀도 체결이 늘 근거가 약합니다(보류 권고). 외부 캔들(GeckoTerminal)로 결정 2,758건을 다시 재도 1·6·24시간 뒤 중앙값이 모두 음수였고 앱의 6시간 뒤 +30%는 재현되지 않았습니다(생존 편향). 며칠 더 돌리기와 범위 확대는 보류가 기본값입니다([검증 보고서](validation-report.md)).

### 3일 계획 실측 (2026-11-11~14, 15풀 · 90초)

실제로 남은 것은 수집 770회(약 19.3시간)입니다. 세션 무응답으로 공백이 4.6시간·48시간 생겼고, 31분 만에 모델 한도로 데스크가 멈춰 판단은 89건뿐입니다. 수집 시간은 중앙값 35.6초, p90 53.7초, 최대 64.7초로 90초 주기 안이었고, 오류는 40회 40건이었습니다. 시장 스냅샷이 있는 자산은 363개(24시간 실행 289개)입니다. Helius 호출은 수집당 37.1건이라 90초 주기면 하루 약 3.6만 건, 30일이면 약 107만 건으로 무료 월 100만과 비슷합니다(대시보드 확인 전). DB는 수집당 약 158KB였습니다. FIRST_SEEN_OBS 자세한 표는 [검증 보고서](validation-report.md).

## 검증 범위

조회 경로와 계산은 모의 HTTP 응답으로 테스트하고, 실제 공개 API로도 실행했습니다. 결과는 [검증 보고서](validation-report.md)에 있습니다.
이 클라우드 환경의 공유 IP에서는 GeckoTerminal이 계속 429를 반환했습니다. 응답 형식은 다른 네트워크 경로의 실제 응답으로 확인했습니다.
