# 학습 루프

결정과 결과를 측정해 **개선안을 제안**하는 폐쇄 루프입니다. 전략 규칙·한도·모델은 자동으로 바꾸지 않습니다.
정책 해석은 [구현 해석](implementation-decisions.md)에 버전으로 고정돼 있으므로 변경은 사람이 검토하고 적용합니다.
작은 모의 표본에 맞춰 규칙을 자동 조정하면 과적합이 되고, 원문 전략의 근거도 흐려집니다.

## 실행 방식

- worker가 `AUTONOMOUS_ENABLED=true`일 때 매시간 `learning:main`을 실행합니다. 읽기 전용 분석이며 주문·장부를 만들지 않습니다.
- `GET /learning?account_id=main`은 마지막으로 저장된 보고서와 제안 목록을 반환합니다.
- `POST /learning/run`(관리 토큰 필요)은 즉시 다시 분석합니다. `lookback_days`는 1~90, 기본 7입니다.
- `POST /learning/proposals/{id}`(관리 토큰 필요)는 제안을 `acknowledged`·`dismissed`·`applied`로 표시하고 감사 기록에 남깁니다.
- 대시보드 **Learning Loop** 화면에서 같은 내용을 볼 수 있습니다.
- 새 테이블 `learning_reports`, `improvement_proposals`만 추가합니다. 기존 테이블은 바꾸지 않으므로 기존 장부를 그대로 사용합니다.

## 측정 항목

| 항목 | 출처 | 알려 주는 것 |
| --- | --- | --- |
| 모델 출력 신뢰도 | `model_usage` | 역할별 통과율, 스키마 실패 수, 상태 분포. 능력 점검은 제외 |
| 게이트 분포 | `decisions` | 어떤 이유로 후보가 막히는지와 비율 |
| 게이트 이후 가격 | `decisions` + 저장된 `data_snapshots` | 결정 후 +1h·+6h·+24h 가격 변화, 이유별 평균·중앙값·왕복 비용 초과 비율 |
| 확률 보정 | BOOK·VET 출력 + 확정 결과 | Brier 점수와 비교 기준(BOOK은 진입가가 내포한 시장 확률, VET는 자신의 기준율) |

가격 변화는 같은 풀(`pair_id`)의 이후 스냅샷만 사용합니다. 허용 오차 안에 스냅샷이 없으면 값을 만들지 않고 건너뜁니다.
왕복 비용 기준선은 정책의 수수료율과 슬리피지 상한으로 계산한 `2 × (0.45% + 2%)`입니다.

## 제안 규칙

| 종류 | 조건 | 제안 내용 |
| --- | --- | --- |
| `MODEL_RELIABILITY` | 역할의 시도 10회 이상, 통과율 80% 미만 | 실패한 필드 확인(`detail`), 스키마·프롬프트 검토 또는 전역 모델 교체 |
| `DATA_COVERAGE` | 결정 30건 이상 중 25% 이상이 자료 결측 사유로 차단 | 검증된 공급원으로 해당 관측 공급. **게이트를 완화하지 않음** |
| `GATE_REVIEW` | 24h 표본 30건·자산 5개 이상, 거부된 후보의 평균이 비용 기준선 초과 또는 허용된 진입의 평균이 음수 | 임계값 검토. 반드시 재생으로 먼저 확인 |
| `CALIBRATION` | 확정 20건 이상에서 BOOK이 시장보다, VET가 기준율보다 부정확 | BOOK 노출 확대 금지·더 큰 edge 요구, VET 사이징 보수화 |

자료 결측으로 막힌 후보는 `GATE_REVIEW`에서 제외합니다. 결측은 임계값이 아니라 자료 공급의 문제입니다.

## 제안의 생명주기

`proposed` → 사람이 `acknowledged`·`dismissed`·`applied`로 표시합니다. 조건이 사라지면 `proposed`만 `withdrawn`이 되고,
사람이 정한 상태는 유지됩니다. 같은 조건이 다시 나타나면 `withdrawn`만 `proposed`로 돌아갑니다.
새 제안이 생길 때와 사람이 상태를 바꿀 때 감사 해시 체인에 기록합니다.

## 해석 한계

- 가격 변화는 가격만 본 값입니다. 체결 깊이·부분 체결·실제 수수료는 반영하지 않습니다.
- 같은 자산이 매 사이클 다시 평가되므로 표본이 겹칩니다. n은 독립 증거 수를 과대평가합니다.
- 보정은 실제로 진입한 거래만 포함하므로 모든 게이트를 통과한 사례로 치우칩니다.
- 합성·재생 계정의 자료는 모델이나 시장에 대한 근거가 아닙니다. 보고서의 `provenance`를 확인하세요.
- 현재 운영 계정에는 진입이 없어 보정 표본이 0입니다. 표본이 쌓이기 전에는 제안이 거의 `MODEL_RELIABILITY`와 `DATA_COVERAGE`로 제한됩니다.
