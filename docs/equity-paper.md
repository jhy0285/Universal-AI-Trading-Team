# 미국 ETF 실시간 모의 운용

[백테스트](equity-backtest.md)에서 고른 전략 `mom12_top5_def`와 벤치마크 `spy_buy_hold`(SPY 보유)를 **실시간으로** 시험합니다. 검증 구간(2020~)은 이미 한 번 열렸으므로(근소하게 기준 미달), 앞으로 쌓이는 이 기록이 유일하게 깨끗한 검증입니다.
PAPER ONLY입니다. 주문·지갑·서명 경로가 없고, 밈코인 거래 장부와 LLM을 쓰지 않으며, 새 테이블 3개(`equity_paper_runs`, `equity_paper_decisions`, `equity_paper_nav`)만 추가합니다.

## 하루에 하는 일

`trading-team equity-paper run` 한 번이 아래를 모두 합니다. 같은 데이터로 다시 실행해도 아무것도 바뀌지 않고(멱등), 며칠 놓쳤으면 따라잡습니다.

1. ETF 16종과 SHY의 일봉을 받습니다(Yahoo 차트, 비공식). 원본 응답의 SHA-256을 모아 하나의 **데이터 해시**로 남깁니다.
2. **확정된 마지막 장까지만** 씁니다(뉴욕 16:30 이후). 장중의 미완성 봉으로 결정하지 않습니다.
3. 고정 규칙이 그 데이터로 내리는 **목표 비중을 결정으로 기록**합니다(`equity_paper_decisions`). 시각(`recorded_at`)과 데이터 해시를 함께 적고, 한 번 쓰면 바꾸지 않습니다. 다음 장이 열리기 전에 기록했으면 `timely = true`입니다.
4. 기록된 결정을 백테스트와 **같은 엔진**으로 재생해 모의 자산을 계산합니다(결정은 종가, 체결은 다음 날 시가, 편도 5bps). 새로 생긴 날만 `equity_paper_nav`에 **덧붙입니다**.

시작일에는 모멘텀 규칙이 월말이 아니어도 그 시점의 목표 포트폴리오로 시작합니다(`target`). 이후에는 규칙대로 월말에만 바꿉니다.

## 믿을 수 있게 하는 장치

| 장치 | 내용 |
| --- | --- |
| 결정 불변 | `(strategy, data_through)`가 유일합니다. 재실행·재계산이 기록된 결정을 덮어쓰지 않습니다 |
| 제때 여부 | 다음 영업일 09:30 뉴욕 이전에 기록했는지를 `timely`로 남깁니다. 놓쳐서 따라잡은 결정은 `false`이며 `late_decisions`로 보입니다 |
| 데이터 추적 | 결정과 자산 행마다 그날 쓴 데이터의 해시를 적습니다 |
| 자산 불변 | 이미 적은 날의 자산은 다시 쓰지 않습니다. 공급자가 과거 가격을 고치면 `revised_days`로 세기만 합니다 |
| 백테스트와 동일 | 모의 자산은 백테스트 엔진의 재생 결과라 둘이 갈라질 수 없습니다. 테스트가 손계산·엔진과의 일치를 확인합니다 |

## 판정 규칙 (전략과 함께 2026-11-10에 고정)

기준은 백테스트와 같습니다: 연수익이 SPY 보유보다 1%p 넘게 뒤지지 않고, 최대 낙폭이 SPY의 60% 이하.
단 **모의 거래일이 252일 이상일 때만** 판정하고, **낙폭 조건은 SPY 자신의 낙폭이 15% 이상일 때만** 판정합니다(그렇지 않으면 `drawdown_not_testable`). 폭락이 없으면 낙폭 비교가 의미가 없습니다. 그 전에는 `insufficient_sample`입니다.
기준을 중간에 바꾸지 마세요. 바꾸려면 결과를 본 뒤의 변경이라고 기록하고 사용자 승인을 받습니다.

## 실행

```bash
DATABASE_URL=sqlite:///.state/equity-paper.sqlite3 .venv/bin/trading-team equity-paper run      # 하루 한 번
DATABASE_URL=sqlite:///.state/equity-paper.sqlite3 .venv/bin/trading-team equity-paper status   # JSON
```

- `equity-paper`는 LLM 설정 없이 돌고, 메인 장부 계정을 만들지 않으며 새 테이블만 만듭니다.
- 워커로 돌리려면 `EQUITY_PAPER_ENABLED=true`(기본 꺼짐)를 켭니다. 서울 07:30(미국 장 마감 후, 다음 개장 전)에 실행하고 시작할 때 한 번 따라잡습니다. 비용은 `EQUITY_PAPER_COST_BPS`(기본 5), 시작 자금은 `EQUITY_PAPER_INITIAL_CASH`(기본 10,000 USD)이며 **처음 시작할 때만** 적용됩니다.
- 상태는 `GET /equity-paper`로도 읽습니다(읽기 전용).
- 두 곳에서 동시에 실행하지 마세요. 유일 제약이 중복을 막지만 실행 하나는 실패합니다.

## 무료 PostgreSQL에 쌓기 (Neon, GitHub Actions)

기록이 컨테이너 디스크에만 있으면 컨테이너가 회수될 때 사라집니다(2026-11-11에 컨테이너가 실제로 재시작됐습니다). 그래서 기록은 Neon 무료 PostgreSQL에 두고, **매일 실행도 GitHub Actions가 합니다**(`.github/workflows/equity-paper.yml`, 매일 22:41 UTC = 07:41 KST, 미국 장 마감 뒤·다음 개장 전). 예약 이벤트가 빠질 때를 대비해 01:17 UTC와 04:53 UTC(10:17, 13:53 KST)에도 예비로 실행합니다. 이미 기록된 날은 다시 써지지 않고(새 결정 0, 새 자산 0일), 동시 실행은 `concurrency`로 막으며, 세 시각 모두 다음 개장(가장 이른 13:30 UTC) 전이라 `timely`가 유지됩니다.

**왜 이 컨테이너가 아니라 GitHub인가.** Claude 클라우드 컨테이너는 인터넷을 HTTP/HTTPS 프록시로만 나가서 Postgres 연결이 Neon 주소를 찾지 못했습니다(2026-11-11 실측: `failed to resolve host`. 같은 주소에 HTTPS로는 응답이 왔습니다). GitHub의 러너는 인터넷에 그대로 나갑니다. 컨테이너에 의존하지 않고 사용자 PC도 필요 없습니다.

**구성**

- Neon 무료 프로젝트(AWS US East 1)의 **직접 연결** 문자열(`-pooler`가 없는 것, `?sslmode=require` 포함). Supabase 무료도 쓸 수 있지만 일주일가량 DB 사용이 거의 없으면 일시중지되고 직접 연결 주소가 기본 IPv6라 설정이 더 듭니다(2026-11 공식 문서 기준).
- GitHub 저장소 비밀 값 `EQUITY_PAPER_DB_URL`에 그 문자열을 넣습니다. 저장한 뒤에는 화면에서 다시 읽을 수 없습니다.
- 워크플로는 이 비밀이 비어 있으면 아무것도 하지 않고 실패합니다(러너의 임시 SQLite에 기록하지 않도록). 단계마다 필요한 곳에서만 비밀을 환경 변수로 넘기고, 실행 뒤 `status`를 로그에 남깁니다.

**사용자가 할 일 (한 번)**

1. GitHub 저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**에서 Name을 `EQUITY_PAPER_DB_URL`, Secret을 Neon 직접 연결 문자열로 해서 **Add secret**을 누릅니다. 채팅에는 붙여넣지 마세요.
2. 워크플로가 main에 들어간 뒤 **Actions** 탭 → `equity-paper-daily` → **Run workflow**에서 `seed_file`에 `records/equity-paper-seed.json`을 적고 실행합니다. 이 한 번의 실행이 지금까지의 기록을 Neon에 올리고 그날 치를 따라잡습니다. 이후에는 매일 저절로 돕니다.

**기록 파일과 복사 도구** (기록은 증거이므로 모두 같은 규칙을 씁니다)

```bash
DATABASE_URL=sqlite:///.state/equity-paper.sqlite3 .venv/bin/trading-team equity-paper export > records/equity-paper-seed.json
DATABASE_URL=<대상 DB> .venv/bin/trading-team equity-paper import records/equity-paper-seed.json
DATABASE_URL=<원본 DB> COPY_TARGET_DATABASE_URL=<대상 DB> .venv/bin/trading-team equity-paper copy
```

- `export`는 비밀이 없는 JSON을 만듭니다(전략, 결정, 자산 행. `records/equity-paper-seed.json`이 2026-11-11 시점의 것입니다). `import`와 `copy`는 같은 규칙으로 씁니다.
- 대상이 비어 있거나 이미 같은 값의 행만 있을 때만 씁니다. 반복해도 같은 결과이고, 그사이 쌓인 날만 덧붙입니다.
- **덮어쓰지 않고 이력을 합치지 않습니다.** 값이 다른 행이 있거나 파일에 없는 행이 있으면 아무것도 쓰기 전에 멈춥니다. 형식이 잘못된 파일(버전, 필드, 시간대 없는 시각 등)도 쓰기 전에 거부합니다.
- 기록 시각, 데이터 해시, `timely`는 그대로 옮깁니다(결정이 먼저였다는 증거가 이사 뒤에도 남습니다).
- `copy`의 대상 주소는 인자가 아니라 환경 변수 `COPY_TARGET_DATABASE_URL`로만 받고, 출력에는 비밀번호를 가린 주소만 찍습니다. `postgres://`와 `postgresql://` 형태는 설치된 드라이버(psycopg 3)로 자동 변환됩니다.

**검증 상태.** 테스트가 SQLite와 PostgreSQL 16에서 통과하고, 실제 기록을 내보내 다른 DB에 가져온 뒤 `status`가 원본과 바이트 단위로 같음을 확인했습니다. **2026-11-11 05:18 UTC의 첫 `Run workflow`(seed_file 지정)가 성공했습니다.** GitHub 러너에서 Neon에 연결했고(가져오기: 실행 2, 결정 3, 자산 2행), Yahoo 일봉을 막힘 없이 받았으며(`data_through` 2026-11-10, 늦은 결정 0), `status`의 값이 컨테이너의 기록과 같았습니다(예: SPY 보유 10,021.459214). 다만 이 실행에서 `mom12_top5_def`의 11-10 자산이 다시 계산하니 저장된 값과 달라(10,055.921374와 10,055.897694, 약 0.02 USD) `revised_days`가 1로 집계됐습니다. 규칙대로 저장된 값은 바꾸지 않았고 원인은 확인하지 못했습니다(공급자가 마감 직후의 값을 나중에 고쳤을 수 있습니다). 이 1일은 이후에도 계속 집계되므로 감시 작업은 이 값을 기준으로 삼고 늘어날 때만 알립니다. **예약 실행:** 첫 예약 시각(2026-11-11 22:41 UTC)에는 실행이 아예 만들어지지 않았습니다(11-12 00:23 UTC까지 `schedule` 이벤트 실행 0건, 늦게 도는 것도 없음). 워크플로는 기본 브랜치(`main`)에 있고 상태는 `active`, cron 문법도 맞습니다. GitHub는 예약이 왜 안 돌았는지 알려주지 않고 이 컨테이너에서는 GitHub 문서 호스트가 막혀 있어, 원인은 확정하지 못했습니다. 그날 기록은 23:21 UTC에 수동 실행(`workflow_dispatch`)으로 남겼습니다(성공, `data_through` 2026-11-11, 늦은 결정 0). 대응으로 cron 줄을 바꿔 예약을 다시 등록하고, 예비 시각 두 개를 더했습니다. **아직 확인하지 못한 것:** 바뀐 예약이 실제로 도는지.

**한계.** 기록 시각은 앱이 적은 값(러너 시계)이며 DB 서버가 찍은 시각이 아닙니다. GitHub의 예약 실행은 몇 분에서 몇 시간 늦거나 건너뛸 수 있고, 늦게 쓰면 `timely`가 `false`로 남습니다. 공개 저장소는 60일 동안 활동이 없으면 예약 실행이 자동으로 꺼질 수 있습니다. 이 컨테이너의 예약 작업은 더는 실행하지 않고, 매일 14:20 KST(05:20 UTC, 세 예약 시각 뒤·다음 개장 전)에 Actions 실행 결과만 확인하는 감시 작업으로 바꿨습니다. 그때까지 예약 실행이 하나도 없으면 감시 작업이 한 번 수동 실행합니다(`.state/equity-paper.sqlite3`는 첫 이틀의 보관용입니다. 두 곳에서 동시에 실행하지 마세요).

## 시작 상태 (2026-11-10)

시작 데이터는 2026-11-09 종가입니다. 모멘텀 전략의 시작 목표는 EEM·QQQ·XLE·XLK·XLV 각 20%(양수 모멘텀 5개가 모두 채워져 SHY는 없음), 벤치마크는 SPY 100%입니다. 첫 모의 거래일은 2026-11-10입니다.

## 한계

- **저장 위치.** 기록은 실행한 곳의 DB에 있습니다. 클라우드 세션의 디스크에 두면 컨테이너가 회수될 때 사라지고, 그러면 사전에 기록한 결정이라는 증거도 함께 잃습니다. 몇 달을 가야 하는 시험이므로 **장기 운용은 사용자 PC나 서버에서, PostgreSQL이나 지속 디스크로** 하세요(`compose.yaml` 참고). 무료 호스팅 PostgreSQL로 옮기는 방법은 위 [무료 PostgreSQL에 쌓기](#무료-postgresql에-쌓기-neon-github-actions)에 있습니다.
- 자산은 부동소수 계산을 소수 6자리로 반올림한 **모의 지수**입니다. 주문 단위 장부가 아니며 분수 주식과 일정한 비용률(5bps)을 가정합니다. 세금·환율·실제 시가 체결 가능성은 반영하지 않습니다.
- 데이터는 Yahoo의 비공식 엔드포인트입니다. 약관·안정성을 보장하지 않으며 조용히 형식이 바뀔 수 있습니다(바뀌면 결정을 기록하지 않고 실패합니다).
- 월말 판정은 마지막 봉에서는 "다음 평일이 다른 달이면 월말"로 합니다. 다음 평일이 휴장이면 결정이 하루 빨리 올 수 있습니다.
- 시료가 얇습니다. 폭락이 와야 낙폭 기준이 평가되므로 판정까지 수개월~수년이 걸릴 수 있습니다.

## 하지 않은 것

- LLM 판단의 평가. 실시간 기록이 쌓이면 LLM 역할을 같은 방식으로 앞으로의 데이터에서만 시험할 수 있습니다.
- 대시보드 화면, 알림.
- 여러 전략 후보의 그림자 운용. 후보를 늘리면 시행 횟수가 늘어 판정이 약해집니다.
