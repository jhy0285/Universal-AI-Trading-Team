# 개선안 검증 흐름 (설계, 미구현)

사용자가 정한 **반자동** 개선의 설계입니다: 학습 루프가 제안하고, AI가 과거 기록으로 검증하고, **사용자가 승인한 뒤에만** 적용합니다. 아직 코드는 없고, 만들기 전에 사용자의 판단을 받으려는 문서입니다.
전략 규칙·한도·모델을 자동으로 바꾸지 않는다는 원칙([학습 루프](learning-loop.md))은 그대로입니다.

## 흐름

| 단계 | 하는 일 | 누가 |
| --- | --- | --- |
| 1. 제안 | `learning:main`이 `improvement_proposals`에 제안을 만듭니다(이미 있음) | 앱 |
| 2. 후보 고정 | 제안마다 **바꿔 볼 값의 후보**를 결과를 보기 전에 기록합니다(예: `CONCENTRATION_CAP` 5% → 7%). 후보 수가 시행 횟수이고, 결과를 본 뒤에는 후보를 더하지 않습니다 | AI, 사용자 확인 |
| 3. 재생 검증 | 저장된 `market` 스냅샷을 `MarketSnapshot`으로 복원해 바뀐 값으로 결정론적 게이트(`scan_gate`, `vet_precheck`, `vet_gate`)를 다시 돌리고, **차단에서 허용으로 뒤집힌 결정**을 모읍니다. 그 풀의 이후 스냅샷(+1h·+6h·+24h)으로 가격 변화를 재어 `gate_regret`와 같은 방법으로 요약합니다. 이후 스냅샷이 없으면 값을 만들지 않고 건너뜁니다 | AI |
| 4. 판정 저장 | 새 테이블 `proposal_verifications`(제안 id, 후보 값과 해시, 입력 기간, 요약, 판정 `supports`/`no_support`/`insufficient`, 정책·코드 버전, 시행 번호)에 쓰고 감사 체인에 남깁니다 | 앱 |
| 5. 승인 | 판정이 `supports`이면 사용자에게 근거를 보여 주고 승인을 받습니다. 적용은 정책 버전을 올리는 코드 변경(PR)이므로 사용자가 승인해야 합니다 | 사용자 |
| 6. 적용 뒤 감시 | 일정 기간 현행과 변경안을 나란히 기록(그림자)해서 악화되면 **되돌리자고 제안**합니다. 자동 되돌림은 하지 않습니다 | 앱, 사용자 |

## 확인한 것과 못 한 것

- **확인함(2026-11-11):** 24시간 실행의 저장된 `market` 스냅샷 200건이 모두 `MarketSnapshot`으로 복원되고 `scan_gate`가 돌아갑니다.
- **확인하지 못함:** 복원한 스냅샷으로 게이트를 다시 돌렸을 때 저장된 결정(차단 사유)을 그대로 재현하는지. 저장된 결정의 일부는 관측 단계(`observer_screen`)에서 막힌 것이라, 같은 결과를 내려면 그 선별 코드도 재생에 포함해야 할 수 있습니다. 구현의 첫 일은 이 재현성 확인입니다(재현이 안 되면 이 검증은 믿을 수 없습니다).

## 검증이 믿을 만하려면

- **판정 기준을 미리 고정합니다.** 뒤집힌 결정의 1시간 뒤 평균 수익이 왕복 비용(4.9%)을 넘고, 자산 단위로 묶었을 때(같은 자산의 반복 표본은 하나로) 표본이 충분하고, 서로 다른 두 기간에서 같은 방향일 때만 `supports`입니다.
- **같은 표본으로 고르고 확인하지 않습니다.** 후보를 고른 기간과 적용 뒤 그림자 기간을 분리합니다.
- **후보가 많을수록 우연히 좋아 보일 확률이 늘므로** 시행 번호와 후보 수를 함께 기록하고 판정에 반영합니다.
- **LLM 판단은 과거로 재생하지 않습니다.** 모델이 과거를 알아 미래 정보가 샙니다. 그래서 이 검증은 게이트를 풀었을 때 *모델이 REJECT를 하지 않았다면* 얻었을 기회의 상한만 알려 줍니다.

## 제안 종류별로 가능한 것

| 종류 | 이 흐름으로 검증 | 비고 |
| --- | --- | --- |
| `GATE_REVIEW` | 가능 | 결정론적 게이트 값의 변경. 위 흐름 그대로 |
| `DATA_COVERAGE` | 게이트 변경이 아님 | 관측 범위를 넓힌 실험을 따로 설계해야 합니다(비용·크레딧 포함) |
| `MODEL_RELIABILITY`, `CALIBRATION` | 불가 | 프롬프트·모델 변경은 과거 재생이 안 됩니다. 앞으로의 실시간 기록으로만 그림자 비교 |

## 지금 데이터로 보면

24시간 실행(2026-11-10~11)에서 차단된 후보의 1시간 뒤 평균 수익은 −2.5%~−4.2%로 모두 비용 기준선(4.9%) 아래였습니다([검증 보고서](validation-report.md)). 이 흐름을 지금 돌리면 게이트를 푸는 모든 후보가 `no_support`가 나올 가능성이 큽니다. **그래서 지금 구현하는 것을 권하지 않습니다.** 검증할 후보(양의 후회를 보이는 게이트)가 생기거나 전략이 바뀌면 그때 만듭니다.
먼저 만든다면 가장 작은 단위는 새 테이블 없이 읽기 전용으로 "이 값을 바꾸면 어떤 결정이 뒤집히고 이후 가격이 어땠나"를 출력하는 스크립트입니다.

## 하지 않는 것

- 자동 적용, 자동 되돌림, 모델 판단의 과거 재생.
- 결과를 본 뒤 후보 추가(시행 횟수 증가이므로 사용자 승인과 기록이 필요).
